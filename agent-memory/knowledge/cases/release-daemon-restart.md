# CASE — Release Pipeline / Daemon Restart

Grep target: `grep -n "CASE-\|<keyword>" knowledge/cases/release-daemon-restart.md`

| ID | Trigger | Fix |
|----|---------|-----|
| CASE-068 | After a release whose `ipcProtocolVersion` bump forces `install-graceful.sh` down its "stopping daemon" path (vs the normal "reusing running daemon" path), reopening Kouen shows session/pane loss and/or panes that had a live process (Claude Code, Codex, a long-running command) reduced to a bare shell. First hit 2026-08-10 after two protocol bumps shipped back-to-back in one session (M10: Claude Code Harness). | **FIXED (partially) 2026-08-10.** Root cause via debug-mantra: `install-graceful.sh`'s only synchronization before killing the daemon was a blind `sleep 1`, racing `SessionStore`'s 0.5s debounced `layout.json` write with **no confirmation the write landed**. Fixed by adding `IPCRequest.flushSessionState` (forces `store.saveImmediately` synchronously, handled in `SurfaceRegistry.handle()`) + `kouen-cli flush-session-state`; `install-graceful.sh` now calls it and waits for the ack instead of guessing, falling back to the old `sleep 1` only if the *currently running* daemon predates the command (the one case it can't help — the daemon about to be replaced). Regression test: `Tests/KouenDaemonTests/FlushSessionStateTests.swift` (asserts a mutation is on disk with **zero** sleep in the test, right after `.flushSessionState` returns). **NOT fixed, separate/orthogonal**: (1) a PTY/agent process dying and the pane coming back as a bare shell is **architecturally inherent**, not a bug — `RealPty` children cannot survive their parent daemon process being killed, and `layout.json` only ever stores topology/cwd, never live process state. `AppDelegate.applicationWillTerminate`'s own comment states the invariant this restart path is the one exception to: "the daemon is owned by launchd and intentionally outlives the GUI — never tear it down on quit." No warning is surfaced to the user before a protocol-bump-forced restart kills every live agent task; that's a real gap but a UX one, not this fix's scope. (2) visual/rendering corruption after reattach to a new daemon PID was reported but never isolated with source evidence — needs a live repro or GUI-side trace (`TerminalHostView`/compositor reattach path) if it recurs. |
